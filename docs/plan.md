# 분할 계획

config 파일 하나로 naive RAG의 검색·생성·채점이 끝까지 돌고 결과가 남는 환경을 만든다. 설계는 `docs/design.md`에 있다.

한 번에 한 단위씩 진행하고, 앞 단위가 머지된 뒤 최신 main에서 다음 단위를 시작한다.

상태: 대기 / 진행 / 승인(사전 리뷰 통과) / 머지

## 단위별 내용

아래에서 쓰는 용어다.

| 용어 | 뜻 |
|---|---|
| 색인 | 문서를 청크로 잘라 임베딩해 Qdrant에 넣어 둔 것. 검색 대상이다 |
| 색인 조건 | 어떤 색인인지를 정하는 값. 청크 크기, 겹침, 청킹 방법, 임베딩 모델과 리비전, 문서 파일 수다 |
| 노드 | 파이프라인의 한 단계를 맡는 함수. 검색, 답 생성이 각각 노드다 |
| 문맥 | 검색으로 가져와 생성 모델에 넘기는 청크들 |
| 근거 문서 | 평가 데이터가 문항마다 "이 문서를 가져와야 맞다"고 지정해 둔 문서 |
| 실행 폴더 | 명령을 한 번 실행한 결과가 담기는 폴더. 검색은 `runs/retrieve/<config 이름>/<실행 시각>/`, 생성은 `runs/generate/<config 이름>/<실행 시각>/`이다 |

### 2. 스캐폴딩

- `uv init --package`로 패키지 뼈대를 만든다.
- 의존성을 설치하고 버전을 lockfile에 고정한다. RAGAS와 LangChain이 함께 설치되지 않으면 멈추고 묻는다.
- 테스트 도구 pytest와, 린터 겸 포매터 ruff를 설치한다.
- ruff 설정을 `pyproject.toml`에 적는다. 규칙은 ruff 기본값에 import 정렬을 더하고, 줄 길이는 100이다.
- 실행한 명령과 버전을 기록한다. 도구가 만든 파일은 리뷰 대상에서 빼고, 직접 고친 부분만 표시한다.

### 3. retrieve 최소 실행

- config 파일에서 검색에 필요한 항목을 읽는다. Qdrant 주소, 청크 크기와 겹침, 임베딩 서버와 모델, 검색 단계의 노드 목록이다.
- config 파일에 정의되지 않은 항목이 있으면 실행 전에 거부한다. 오타로 적은 항목이 조용히 무시되는 일을 막기 위해서다. 예를 들어 `overlap`을 `overlp`로 적으면 거부한다.
- 문서 폴더와 평가 파일의 경로는 `.env`의 `DOCS_DIR`과 `EVAL_FILE`에서 읽는다. 평가 파일에서는 문항의 `id`와 `question`을 읽는다.
- 색인 조건(청크 크기, 겹침, 청킹 방법, 임베딩 모델과 리비전, 문서 파일 수)으로 색인 이름을 계산한다. 그 이름의 색인이 Qdrant에 있으면 재사용하고, 없으면 오류로 멈춘다. 새로 만드는 기능은 8번에서 더한다.
- 노드마다 config에서 부를 이름을 붙여 둔다. config의 `retrieve` 목록에 그 이름을 적으면, 적힌 순서대로 노드를 이어 실행한다. 예를 들어 `- search: {mode: dense, top_k: 5}`라고 적으면 `search`라는 이름의 노드가 그 인자로 실행된다.
- `search` 노드를 만든다. 질문을 임베딩해 색인에서 가장 가까운 청크 `top_k`개를 가져온다.
- `retrieve` 명령이 문항마다 검색해, 결과 파일 `contexts.jsonl`과 config 사본을 `runs/retrieve/<config 이름>/<실행 시각>/`에 쓴다. `configs/naive.yaml`로 실행하면 `runs/retrieve/naive/YYYYMMDD-HHMMSS/`가 된다.
- GPU 없이 도는 테스트 환경을 만든다. 임베딩은 가짜로, Qdrant는 메모리 안에서 돌린다.

### 4. 유출 방지

- 추적과 사용 통계 전송을 끄는 환경변수가 빠지면 패키지를 불러오지 못하게 한다.
- 이 프로세스가 장비 밖으로 접속하려 하면 오류를 내게 한다.
- config의 서버 주소가 로컬 주소가 아니면 거부한다.
- 필요한 환경변수를 `.env.example`에 적어 둔다.

### 5. 서버 띄우기

- 서버 정의 파일 `configs/servers.yaml`에 서버마다 컨테이너 이미지, 모델과 리비전, 포트, GPU 몫, 실행 인자를 적는다. 대상은 Qdrant와 임베딩·생성·채점 모델 서버다.
- `serve start <역할>`이 그 정의대로 docker 컨테이너를 띄우고, 서버가 응답할 때까지 기다린다.
- `serve stop <역할>`이 컨테이너를 내린다.

### 6. 검색 지표

- 평가 파일의 필드 이름을 config의 `eval.fields`에 적힌 대로 읽는다. 평가 파일마다 필드 이름이 달라도 config만 고치면 되게 하기 위해서다.
- 문항마다 Recall, Precision, MRR, nDCG를 `eval.k`의 순위마다 계산한다. 근거 문서가 지정되지 않은 문항은 대조할 대상이 없으므로 뺀다.
- 전체 평균과 문항 유형별 평균을 낸다.
- 문항별 점수는 `scores.jsonl`에, 평균은 `metrics.json`에 쓴다.

### 7. 실행 기록과 부분 실행

- 실행 폴더에 `run.json`을 쓴다. 명령, git 커밋, 문서 수, 평가 파일 해시, 색인 이름, 소요 시간을 담는다.
- `retrieve --limit N`으로 평가 파일의 앞 N문항만 돌릴 수 있게 한다.

### 8. 색인 새로 만들기

- 같은 조건으로 만들어 둔 색인이 없을 때, 3번처럼 멈추지 않고 새로 만든다.
- 문서를 임베딩 모델의 토큰 수 기준으로 청크로 자른다.
- 청크를 임베딩해 Qdrant에 넣는다. 나중의 혼합 검색을 위해 BM25 벡터도 함께 넣는다.
- 다 넣은 뒤에만 색인에 완성 표시를 붙인다. 완성 표시가 있는 색인만 재사용한다.
- 만들다 중단돼 완성 표시가 없는 색인은 지우고 처음부터 다시 만든다.
- 겹침이 청크 크기 이상이거나 청크 크기가 임베딩 모델의 입력 한도를 넘으면 실행 전에 거부한다.

완성 표시로는 Qdrant의 별칭을 쓴다. 별칭은 저장된 색인에 붙이는 또 하나의 이름이다. 자세한 규칙은 `docs/design.md`의 "색인"에 있다.

### 9. generate

- config 파일에서 생성에 필요한 항목을 읽는다. 생성 서버와 모델, 토큰 한도, 온도, 생성 단계의 노드 목록이다. 문맥이 생성 모델의 토큰 한도를 넘는 구성은 거부한다.
- 프롬프트 틀에 문맥과 질문을 채워 생성 모델을 부르는 `answer` 노드를 만든다.
- `generate` 명령이 검색 실행 폴더의 결과를 읽어 문항마다 답을 만들고 `results.jsonl`에 쓴다.
- config의 검색 조건이 그 검색 실행에 쓰인 조건과 다르면 거부한다.

### 10. score

- config 파일에서 채점 서버와 모델 항목을 읽는다.
- 생성 실행 폴더의 답을 RAGAS의 세 지표(Faithfulness, Response Relevancy, Factual Correctness)로 채점한다.
- 전체 평균, 문항 유형별 평균, 근거 문서를 가져왔는지에 따른 평균을 낸다. 점수가 빈 문항의 수도 적는다.

### 11. compare

- `runs/` 아래의 실행 폴더를 읽어 검색 실행끼리, 생성 실행끼리 지표 표를 출력한다.

### 12. 서버 내려받기와 대조

- `serve download <역할>`이 컨테이너 이미지와 모델 파일을 내려받는다. 외부 접속이 허용되는 유일한 명령이다.
- `retrieve`, `generate`, `score`가 시작할 때 서버에 떠 있는 모델과 리비전이 config와 같은지 확인하고, 다르면 멈춘다.
- 확인한 서버 모델을 `run.json`에 적는다.

### 13. 실제 서버 검증

- 장비의 실제 서버로 500문항을 검색, 생성, 채점까지 돌린다.
- 작은 문서 폴더로 색인을 새로 만들어 본다.
- 단계별 소요 시간을 기록한다.
- 코드는 바꾸지 않는다. 문제를 발견하면 재현 테스트와 함께 별도 단위로 고친다.

### 14. README

- 준비물, 서버 띄우기, 실행 순서, 결과 읽는 법, 새 노드를 더하는 법을 적는다.

## 진행 방식

- 2번부터는 실행 장비에서 개발한다.
- 3번부터는 사전 리뷰의 "직접 확인하기"에 실제 서버로 돌리는 명령을 넣는다.
- 매 단위의 검증에서 `uv run pytest`, `uv run ruff check`, `uv run ruff format --check`를 실행한다.

## 개발자 준비 항목

| 시점 | 할 일 |
|---|---|
| 1번 전 | GitHub 비공개 원격 저장소를 만들고 squash 머지만 허용한다 |
| 2번 전 | 장비에 개인 전역 규칙 파일을 옮긴다 |
| 2번 전 | 장비에 uv, Python 3.12, docker, nvidia-container-toolkit이 있는지 확인한다 |
| 3번 뒤 | `.env`에 `DOCS_DIR`과 `EVAL_FILE`을 적는다 |
| 3번 뒤 | 장비에 이미 만들어 둔 색인에 새 색인 이름을 붙인다. 명령은 3번의 사전 리뷰에 적는다. 붙이기 전에 장비에서 `retrieve`를 돌리면, 8번이 머지된 뒤에는 문서 전체의 색인을 새로 만들기 시작한다 |
| 5번 전 | 채점 모델을 장비에서 띄울 때 쓴 vLLM 이미지 버전과 인자를 알려 준다 |
| 5번 전 | 임베딩, 생성, 채점 모델이 고정 리비전으로 `HF_HOME`에 있는지 확인한다 |
| 선택 | 장비 방화벽에서 외부 송신을 차단한다. 컨테이너의 송신까지 막는 유일한 방법이다 |

## 범위 밖 (만들지 않는다)

- 혼합 검색, 리랭킹 등 naive RAG 밖의 노드와 분기·반복 그래프
- LLM 기반 검색 지표(Context Precision, Context Recall), 벤치마크 공식 지표, `answer_facts` 사용
- 문서 내용 변경 감지
- 서버 자동 교체, 명령 하나로 끝까지 도는 실행
- 실험 추적 서버
- CI와 커밋 전 훅
- 문서 변환·정제, OCR, PDF 파싱, 여러 문서 출처
